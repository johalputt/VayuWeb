## Abstract

This proposal replaces the resolver's provisional browser-security posture with a normative,
deny-by-default profile, and adds a **Private Mode** in which all egress is routed through an
anonymising transport and nothing durable is written to disk.

Concretely it adopts [CONTENT-SECURITY.md](CONTENT-SECURITY.md) and [PRIVACY.md](PRIVACY.md) as
normative, tightening the Content-Security-Policy from `default-src 'self'` with `'unsafe-inline'`
styles to `default-src 'none'` with no inline anything; adding ten accompanying response
headers; specifying exactly which request and response headers the proxy strips; naming the four
channels CSP cannot close and specifying what closes them instead; and introducing a single
guarded egress choke point that fails closed.

## Motivation

The resolution specification shipped with a provisional CSP. It was a reasonable first pass and it
has three defects that matter.

**It permits `'unsafe-inline'` for styles.** Inline CSS is an exfiltration channel — an attribute
selector combined with a `url()` leaks document content one character at a time — and it is the
relaxation that most often drags script injection back in through `style` attributes.

**It permits `data:` in `img-src`.** Attacker-controlled bytes rendered without a fetch, for no
benefit: every asset a VayuWeb page needs is already inside its own verified CID.

**It is silent about everything CSP does not cover.** WebRTC will disclose the reader's real IP
address to any page that can run a script, regardless of the policy. Top-level navigation is an
open exfiltration channel because `navigate-to` never shipped. `<link rel="dns-prefetch">`
produces a clearnet DNS query — precisely the leak VayuWeb exists to prevent — and no CSP directive
governs it. A profile that closes nine channels and stays quiet about four is not a strict
profile; it is a misleading one.

There is a second motivation, of equal weight. Constitution Article 14 makes privacy of resolution
a **right**, and Article 44.8 requires that rights be checked by the same conformance machinery as
wire correctness, in the same run. A right without an executable test is an aspiration. This
proposal supplies the tests.

## Specification

The normative text is in two documents, adopted in full:

- **[CONTENT-SECURITY.md](CONTENT-SECURITY.md)** — the Content-Security-Policy, the accompanying
  response headers, request-header hygiene, response-header stripping, markup neutralisation, and
  an explicit section on what CSP cannot close.
- **[PRIVACY.md](PRIVACY.md)** — the two modes, the single egress choke point, fail-closed
  behaviour, the complete inventory of what is written to disk, browser-side traces, memory
  hygiene, the prohibition on telemetry, and the panic action.

Summarised, the substantive changes are:

1. `default-src` becomes `'none'`. Every resource type is enumerated explicitly, so a directive
   nobody remembered to add fails closed.
2. `'unsafe-inline'` is removed from `style-src`; `data:` is removed from `img-src`; `blob:` is
   removed from `media-src`; `'wasm-unsafe-eval'` is removed from `script-src`.
3. `require-trusted-types-for 'script'` and `trusted-types 'none'` are added.
4. Ten response headers are added, including a `Permissions-Policy` denying every powerful
   feature with an empty allowlist, `Referrer-Policy: no-referrer`, the COOP/COEP/CORP triple, and
   `X-DNS-Prefetch-Control: off`.
5. No CSP reporting endpoint is configured, deliberately — a report endpoint is an outbound
   channel that fires exactly when something unexpected happens.
6. The resolver emits a **byte-identical request header set from every install**, which is a
   stronger and more testable property than "strips identifying headers".
7. A single guarded egress constructor becomes the only way any component may open a socket,
   enforced at build time.
8. Private Mode routes all egress through an anonymising transport, keeps all state in memory, and
   **refuses to start** if the transport is unavailable — with no fallback, no queue and no
   override.
9. Per-site relaxations for WASM and Trusted Types are defined, scoped to a single site, and
   required to be visible to the reader.

## Security considerations

**What this closes.** All same-origin-violating subresource loads; inline script and style
execution; DOM-XSS sinks; plugin execution; framing and clickjacking; `<base>` hijacking;
cross-origin size and timing probes; speculative DNS; cookie setting; MIME confusion; and — via
the full-proxy requirement — top-level navigation exfiltration.

**What it does not close, and how.** WebRTC IP disclosure is closed by disabling WebRTC in the
client's webview, and is a documented residual for third-party browsers rather than a solved
problem. Same-origin timing side channels are not closable. Content-level social engineering is
not a technical problem. A compromised endpoint defeats everything here.

**New attack surface introduced.** Two things. First, the per-site relaxation mechanism in
CONTENT-SECURITY.md section 1.3 is a widening path, and a widening path is a target; it is
mitigated by being per-site, non-persistent across sites, and surfaced in the UI. Second, Private
Mode's fail-closed behaviour is a denial-of-service primitive — an adversary who can disrupt the
anonymising transport can stop the resolver. That trade is accepted deliberately: a resolver that
has stopped is safe, and a resolver that has fallen back is not.

**Testable claims only.** Every control above corresponds to a conformance test in
CONTENT-SECURITY.md section 6 or PRIVACY.md section 10, each asserting on observed behaviour — the
socket set, the filesystem write set, the emitted bytes — rather than on configuration.

## Privacy considerations

The zero-egress test is the load-bearing one: resolve a name, load a page, and assert under a
socket monitor that the observed connection set contains only VayuWeb peers. It fails on *any* other
socket, which means it catches leaks introduced by future code that nobody thought to review.

Private Mode additionally closes the network layer, which no header can reach. Its cost is real —
slower resolution and a cold start every launch — and readers should choose it deliberately rather
than have it chosen for them, which is why it is a mode rather than a default.

This proposal does **not** claim anonymity. Constitution Article 24 forbids that claim and
Article 21 requires the limits be stated as plainly as the capabilities; PRIVACY.md section 11
does so, and no summary of this work anywhere — repository, website or release note — may state
otherwise.

## Rights-impact analysis

| Title II Article | Effect |
|---|---|
| Article 13 — the right to read anonymously | **Expansion.** Private Mode closes the network layer; the zero-egress test makes the guarantee checkable rather than asserted. |
| Article 14 — the right to privacy of resolution | **Expansion.** Supplies the executable outbound-connection test the Article requires. |
| Article 12 — the right to publish and be reachable | **Restriction, minor.** Sites using inline styles, inline scripts, `data:` images or WASM must change to be rendered. Justified: each of those is a named exfiltration or execution vector, the migration is mechanical, and the per-site relaxations in CONTENT-SECURITY.md section 1.3 cover the cases that genuinely need them. |
| Article 16 — the right to interoperate | **None.** The profile is fully specified in normative text; an independent implementation can reproduce it byte-for-byte, which is what test 1 checks. |
| Article 19 — the right to unpublish | **None.** |

The restriction on Article 12 is the one reviewers should attack. It is a real cost imposed on
publishers to protect readers, and reasonable people can disagree about where that line sits.

## Impossibility-and-capture analysis

Required by Constitution Article 5.

**What this makes impossible.** A VayuWeb page contacting a third party. Not "discouraged", not
"logged" — the socket does not open, and the build fails if any code path could open it. Likewise
a durable record of what was read in Private Mode: the write never happens, so there is nothing to
subpoena, seize, or subsequently be persuaded to hand over.

**What this makes worth capturing.** Two things, and both are named rather than hidden.

The **anonymising transport** becomes load-bearing in Private Mode. If it were a single provider,
this proposal would have created exactly the chokepoint Article 4 forbids — so the transport MUST
be pluggable and MUST NOT ship with a single hard-coded provider, and that requirement is part of
this proposal rather than a footnote.

The **per-site relaxation mechanism** is a lever for widening the policy. It is constrained to
per-site scope with mandatory UI disclosure, and any proposal to make a relaxation global should be
treated as an attack on this VWIP regardless of the reasoning offered.

## Centralisation analysis

Required by Constitution Article 4. Parties whose withdrawal would degrade the mechanism:

| Party | Dependency | Justification |
|---|---|---|
| Anonymising transport operators | Private Mode cannot run without a working transport | Mitigated by requiring the transport to be pluggable with no hard-coded default provider. The dependency is on *a* transport, never on *one* operator. |
| Browser vendors | The profile depends on engines implementing CSP, Permissions-Policy and COOP/COEP correctly | Irreducible for any system rendering in a browser. Mitigated by belt-and-braces headers, so a single engine gap does not open a channel — `X-Frame-Options` alongside `frame-ancestors` is the pattern. |

No other party is required. In particular this proposal introduces no service, no endpoint, no
reporting sink and no default provider of any kind.

## Migration and rollback

**Migration.** No registry state changes, no wire format changes, no key handling changes. The
change is entirely within the resolver, and any peer implementing this profile interoperates
unchanged with any peer that does not.

Publishers whose sites use inline styles or scripts must move them into files within the same CID.
Since there are no deployed VayuWeb sites, the present migration cost is zero — which is precisely
why this proposal is made now rather than after a corpus exists. Adopting a strict profile before
anyone has published is free; adopting it afterwards is a breaking change to every site at once.

**Rollback.** Revert the resolver to the previous headers. Nothing persists, and no published
content becomes invalid. Rollback is a one-line change with no data migration, which is the
strongest form of reversibility available.

## Activation epoch

**Phase 3 of the roadmap**, at the point the resolution proxy first serves a page — strictly in
the future, as Constitution Article 47 requires. Since no resolver exists yet, the profile is the
initial behaviour rather than a change to deployed behaviour, and no reader is ever served under
the weaker policy.

## Expiry of transitional mechanisms

Required by Constitution Article 48.

| Mechanism | Expiry |
|---|---|
| Per-site `'wasm-unsafe-eval'` relaxation | Reviewed at the first decennial review (Article 58), and removed if a safer WASM integration exists by then |
| Per-site named Trusted Types policy | Same |
| Standard Mode clearnet passthrough (PRIVACY.md 3.2) | No expiry; a permanent, disclosed, non-default option |

## Test vectors

Twelve executable tests, specified in CONTENT-SECURITY.md section 6 and PRIVACY.md section 10. The
five that must pass before this proposal can reach Implemented:

1. **Zero-egress.** One resolution plus one page load under a socket monitor; observed connections
   are VayuWeb peers only.
2. **Fail-closed.** Private Mode with the transport killed; the resolver stops, and no direct
   connection is attempted.
3. **No-trail.** A Private Mode session under a filesystem monitor; zero durable writes.
4. **Byte-identical headers.** The three canonical values emitted exactly as written here.
5. **Uniform requests.** Two installs, different machines, identical outbound request headers.

Test 1 is the one this whole proposal exists to make possible.

## Backwards compatibility

No compatibility break at the protocol level: no registry, wire, key or naming change. The break
is at the authoring level, for site content that does not exist yet.
